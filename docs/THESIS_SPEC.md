## 1. 总体目标

本项目的最终目标是完成一篇关于**视觉文档检索与证据定位**的毕业大论文。研究对象不是普通纯文本检索，而是包含页面图像、OCR 文本、版面区域和表格等结构信息的视觉文档。

毕业论文需要回答的核心问题是：

> 如何在保持视觉文档检索效率的同时，让检索结果不仅能命中正确页面，还能可靠地定位页面内支持答案的证据区域，并为后续可信生成提供结构化证据。

毕业论文不应从一个过大的“完整 RAG 系统”开始，而应从一个可验证的小论文方法逐步扩展。小论文负责证明一个清楚、可复现的检索方法；毕业论文在此基础上扩展数据、模型、证据组织和生成验证能力。

### 1.1 非目标（现在不做）

- 不做端到端生成大模型训练，不做拒答分类器训练（大论文后期才评估生成与引用）。
- 不复现全部三篇阅读论文的完整训练，只读原文、只复现 Phase 1C 所需的无训练基线。
- 不在小论文阶段引入中文年报 evidence set 上一代遗产。那套 `cn_annual_reports + evidence set + sufficiency/verify/citation` 是开题后被否掉方向的产物，已归档，不再维护，不进主线。

## 2. 小论文与毕业论文的关系

### 2.1 小论文的任务

小论文是毕业论文的第一阶段研究，不是独立于毕业论文之外的临时实验。它聚焦一个窄问题：

> ColPali 的视觉 patch 表示能找到相关页面，但是否能充分利用 OCR 和布局结构来改善页面内证据定位？

小论文的最终方法应包含真实的网络修改或可学习模块，而不能只做：

- 证据集重新组织；
- 固定规则的 BBox 聚合；
- 推理阶段的分数传播；
- 只比较已有模型而不改变表示。

小论文拟研究的方向是：在 ColPali 的原始页面 patch 表示上，加入 OCR 文本、BBox 和区域类型，通过 patch 与布局区域之间的稀疏局部对应关系，学习新的文档侧 patch 表示。

约束（硬约束，投稿时如实写）：

```text
1. 不裁剪区域子图、不重复运行视觉编码器；
2. 保持 late-interaction / MaxSim 检索接口；
3. 文档侧 query-independent：P_fused 离线算好，所有 query 共用。
```

代价（必须在 Discussion 主动承认）：不能随 query 动态改变文档表示；一个 patch 压住多个主题时可能互相污染；OCR 错误可能污染视觉表示。详见第 11 节风险。

### 2.2 毕业论文的扩展方向

小论文完成后，毕业论文可以沿以下方向扩展：

1. 从单一数据集扩展到多个视觉文档数据集和中文年报场景；
2. 从页面检索和区域定位扩展到证据集构建；
3. 从检索指标扩展到基于证据的回答生成、引用和拒答；
4. 研究 OCR 错误、复杂表格、跨页证据和长文档条件下的鲁棒性；
5. 分析视觉信息、文本信息和布局信息在不同查询类型下的作用；
6. 验证该局部融合机制在更高分辨率、不同网格切分逻辑的视觉语言模型上的通用性（大论文阶段才做；小论文绑死 448 ColPali 以控制变量）。

这些扩展必须建立在小论文已验证的表示融合模块和实验协议之上，而不是重新开始一个完全不同的系统。

大论文扩展时，证据集、生成、引用才首次成为正式对象。小论文阶段出现这些词，只能表示“未来工作”，不能作为方法或贡献。

## 3. 研究主线

整体技术链路为：

```text
页面图像 + OCR/Layout
        -> 文档页面表示
        -> 页面级检索
        -> 页面内证据区域定位
        -> 证据区域组合为 evidence set
        -> 可选的回答生成与证据验证
```

当前小论文只覆盖前四步。证据集、生成和验证属于毕业论文后续阶段，不能在小论文实验尚未稳定时提前扩张范围。

### 4.3 已核实的五个关键事实（纠正调研文件里的二手说法）

1. **GPT-5 描述子属实。** Beyond 附录 7.2/7.3 明确写用 GPT-5 生成整体结构描述，只描述构图和空间排列，不转录细节。训练集 ColPali 118k + 500 dev，每条加一条离线描述子。
2. **BFS 组框属实。** RegionRAG 附录算法 S1 全文就是 BFS 队列找连通分支，不是推测。
3. **门控残差要分开说。** Argus 有门控残差（公式 F=G+σ(α)Sshared+σ(β)S），ColMate 没有（全文无 Gate、无 residual fusion）。不能混说“它们都有门控”。
4. **ViDoRe V3 不能当区域评测。** Argus 报的 V3 是 8 个公开域页级 NDCG@10，外加 agent 包装。无 IoU、无框。区域评测只能用 MMDocIR 布局级 + IoU Hit，V3 只能当页级泛化补充。
5. **OCR 天花板 85%。** Snappy 在 BBox-DocVQA 上失败 487 个里 414 个（85%）是 OCR 根本没切出与 GT 重叠 ≥0.5 的框，传播再好也选不出来。只有 15% 是选错。这个数字必须进我们的 Limitation，否则“控制成本、提升定位”就是空话。

### 4.4 一句话防御线（related work 怎么写）

- 对 Snappy：共享 overlap 思想，但它是推理期分分数、不改表征；我们是离线改表征。它是 Phase 1C 最强基线。
- 对 Beyond：它是自顶向下全局 token + 文本结构监督；我们是自底向上坐标级局部融合 + 页内区域评估。它不做后半句。
- 对 ColMate：它的空间只在预训练 loss 的 Bj pooling；我们是前向显式融合层。位置不同。
- 对 LFRAG/ColParse：它们用 k+1 次视觉编码换布局/存储；我们用 0 次额外编码换定位。路线相反/代价不同。
- 对 Argus：它是 query-conditioned 在线 D(q)；我们是 query-independent 离线 P_fused。这是部署 trade-off，不是高低之分，Argus 只能当未来工作。
- 对 MM-Matryoshka/ColChunk/SAP：压缩正交，可组合，我们的 P_fused 可以是它们的输入。

## 5. 小论文的正式研究问题（含操作定义）

### RQ1：页面命中是否等于证据命中？

使用冻结的 ColPali 页面级检索结果，分别统计：

- A：页面命中且区域命中；
- B：页面命中但区域未命中；
- C：页面未命中但其他方法能够找到证据区域；
- D：页面和区域均未命中。

操作定义（执行手册 `docs/PAPER_SPEC.md` 必须照此实现，不得临时改）：

```text
页面命中：gold 页在 Top-K（K 预先声明，如 5）内。
区域命中：预测框与 gold 框 IoU ≥ 0.5（阈值预先声明，dev/test 一致）。
候选框：只能来自 OCR/Layout 解析结果；gold 框只用于评测。
多框覆盖：一个 patch 压住多个框时权重必须归一化，不得重复送分。
分层：按区域类型、面积、OCR 密度分层报告；至少保存 10 成功 + 10 失败可视化。
```

如果 B 类在 dev/test 规则下稳定存在，才能证明页面级检索不足以代表证据定位正确，并继续研究区域方法。

### RQ2：固定布局区域和查询相关显著区域各有什么优缺点？

比较已有 OCR/Layout BBox 的固定聚合，与基于 patch relevance map 的动态显著区域分组。该阶段是无训练诊断和 baseline，不应被表述为完整复现 RegionRAG。

必须包含 Snappy 式传播（公式 rel=ΣIoU·score/ΣIoU，max/mean/IoU 三聚合对比）。Snappy 的坐标映射（G=32, I=448, s=14，OCR 框缩放到模型坐标）必须先审计通过。

### RQ3：能否在不裁剪页面和重复视觉编码的前提下学习更好的 patch 表示？

如果无训练方法仍存在稳定缺口，训练一个布局约束的文档侧 patch 融合模块，并检验它能否同时保持页面检索能力、改善区域定位能力和控制额外计算成本。

回答形式必须是三指标同报：页级（Recall/MRR/nDCG）+ 区域级（Region Recall/MRR/IoU Hit@0.5）+ 效率（向量数/索引/离线融合/在线延迟/显存）。只涨一处不算成。

## 6. 小论文方法设计

### 6.1 输入

- ColPali 视觉编码器产生的页面 patch 表示 `P = {p_i}`；
- OCR 区域文本；
- 每个区域的 BBox 坐标；
- 区域类型（文本、标题、表格、图像等，若数据提供）。

### 6.2 布局节点编码

每个布局区域编码为：

```text
t_j = TextLayoutEncoder(ocr_text_j, bbox_j, type_j)
```

第一版使用轻量文本投影、坐标编码和类型嵌入，不直接引入大型 LayoutLM/UDOP，以控制变量和显存。OCR 特征必须过投影层，不能因维度相同直接相加。坐标建议加正弦 2D 编码（LayoutLMv3 式），增强物理感知。

### 6.3 Patch-Region 软对应（含坐标审计）

根据 patch 和 BBox 的空间关系计算对应权重。开发阶段比较：

- intersection / patch area；
- intersection / region area；
- IoU。

只能在独立 dev 集确定一种规则，最终 test 不得重新调参。

**坐标审计是硬 Gate（Phase 1 前置）：** PaliGemma 默认 448×448、32×32 网格，OCR 框是原图绝对像素。必须先验证 resize/padding/patch 网格与 BBox 对齐，否则 W_ij 全错且静默失败。审计输出格式在执行手册定义（缩放公式、可视化抽查、越界处理）。

空区域处理：大面积留白 patch 可能 W_ij=0，必须规定兜底（跳过融合保留原 P，或可学习背景 token），防止 NaN/梯度爆炸。K、邻域规则、空处理一律 dev 冻结。

### 6.4 稀疏局部融合

对于每个视觉 patch，只选择与其重叠或邻近的少量布局节点：

```text
N(i) = TopKRegions(patch_i, overlap_or_distance)
delta_i = LocalCrossAttention(p_i, {t_j | j in N(i)}, spatial_bias)
p_i' = p_i + gate_i * residual(delta_i)
```

这里的关键研究贡献是：在不重新裁剪页面的情况下，利用布局约束学习新的 patch 表示，并继续通过 ColPali 的 late-interaction/MaxSim 接口完成检索。

Gate、残差和零初始化属于训练稳定性设计，不能分别包装成独立算法创新。零初始化目标是训练起点退化为原版 ColPali，OCR 噪声扰动实验必须验证“污染时 Gate 自动关小、保底退回原性能”。

区域评分聚合必须归一化；页面与融合分数融合必须先归一化，权重 dev 定或预先固定。

### 6.5 文档侧的含义

“文档侧”表示融合后的 `P'` 在离线建库阶段由页面图像和 OCR/Layout 计算得到，与具体 query 无关。在线阶段只需编码 query，并与已经保存的 `P'` 做 MaxSim。

优点是可以预计算并保持现有索引接口；限制是不能像 query-conditioned 方法（如 Argus）那样针对每个 query 动态改变文档表示。该限制需要在论文中如实说明，并将 Argus 列为相关工作/未来方向。

## 7. 阶段化开发路线

### 阶段 0：研究和环境冻结

目标：建立唯一、可理解、可复现的实验项目。

要求：

- 只使用一个 uv 项目环境和一个 `.venv`；
- 固定 Python、PyTorch、CUDA、ColPali 版本；
- 明确数据来源、版本和路径；
- 写出实验协议和指标定义；
- 不在结果尚未核验前写论文结论。

产出：环境检查记录、数据说明、实验协议、项目 README。

补充：阅读任务只有两项——补实 Beyond 笔记（含是否用 OCR/BBox、注入位置、是否更新局部、是否报区域），核对 ColMate/LFRAG/RegionRAG/Argus 的表示位置与推理接口。不开新阅读支线。

### 阶段 1：页级 baseline（Phase 1A）

方法：BM25、文本 dense、Hybrid、ColPali。

目标：获得可信的页面级分数，作为后续区域实验的比较基准。

最低记录：query 数、页面数、数据 split、配置文件、代码 commit、运行时间、输出目录和指标文件。全量 MMDocIR evaluation 应为 1658 query，行数对不上不登记 baseline。

### 阶段 2：页面-区域缺口诊断（Phase 1B）

目标：统计 RQ1 的 A/B/C/D 四类样本，并保存可复核的错误案例。按类型/面积/OCR 密度分层 + 可视化。

只有当“页面命中但区域未命中”在 dev/test 规则下表现为稳定问题，才进入下一阶段。注意 MMDocIR evaluation 有布局 gold 的 query 约 1598/1658，无框 query 只做页级，不混入区域分母。

### 阶段 3：无训练区域 baseline（Phase 1C）

至少比较：

1. 原始 ColPali 页面检索；
2. Snappy-style BBox 分数传播（含坐标映射审计）；
3. 固定 IoU/coverage 的区域聚合；
4. 基于 patch relevance map 的动态显著区域分组（不许叫 RegionRAG 复现，因无其训练期全局/局部对齐与区域监督）。

目标：判断规则方法能解决多少缺口，以及剩余错误是否值得训练新模块。若 Snappy 已解决大部分问题，论文转向失败类型与效率分析，不强行训练。

### 阶段 4：训练 patch 融合模块（Phase 2）

前提：阶段 2 和阶段 3 已完成，且有独立训练或开发数据。MMDocIR evaluation gold 不能同时当训练监督和最终测试。

训练顺序：

1. 冻结 ColPali，只训练布局节点编码器、局部注意力、投影和门控参数；
2. 先在 dev 上确认训练稳定；
3. 如确有必要，再用 LoRA 微调部分 ColPali 参数（3080Ti 12GB 下 batch 1/2/4，需先评估显存）；
4. test 集只在模型、超参数和映射规则冻结后使用。

候选损失：

```text
L = lambda_page * L_page
  + lambda_region * L_region
  + lambda_distill * L_distill
```

- `L_page`：保持正确页面排序；
- `L_region`：提高正确证据区域相对无关区域的分数；
- `L_distill`：约束融合表示不要严重破坏原始 ColPali 排序。

权重 dev 定。OCR 噪声扰动消融必做。

### 阶段 5：消融、效率和最终测试

消融变量：无 OCR、无布局 bias、无区域类型、无坐标、hard/soft mask、三种 overlap 定义、无 Gate、无蒸馏、不同 K。

效率记录：向量数量、索引大小、离线编码/融合时间、在线 query 延迟、Top-K 重排时间、峰值显存。必须与 ColParse/LFRAG 的 k+1 次编码成本同表对比，否则“控制成本”无意义。

最终测试必须使用冻结配置，并记录完整运行元数据。任何 test 结果都不得反向用于选择方法。

## 8. 数据和评测规范

### 8.1 数据划分

训练、开发和测试数据必须明确分离。MMDocIR evaluation gold 只能用于最终评测，不能同时作为训练监督和最终测试依据。

补充：MMDocIR evaluation=313 文档/1658 query/2107 页级标签/2638 布局标签；训练集 6878 文档/73k+ query（含部分布局标签，可作为 Phase 2 候选，需先检查标签构造规则）。ViDoRe V2 可做页级泛化补充；ViDoRe V3 不做区域评测（见 4.3）。

### 8.2 页面级指标

- Recall@1、Recall@5、Recall@10；
- MRR；
- nDCG@5、nDCG@10。

### 8.3 区域级指标

- Region Recall@1、Recall@5；
- Region MRR；
- IoU Hit@0.5（阈值需要预先定义）；
- Text Recall / Text F1（辅指标，防 IoU 误杀，定义见下）；
- 页面命中与区域命中的 A/B/C/D 分解。

Text Recall/F1 定义（tokenization 预先声明：中文按字、英文按词、统一小写去空格）：

```text
Text-Recall(R_pred, R_gold) = |Tok(R_pred) ∩ Tok(R_gold)| / |Tok(R_gold)|
Text-F1 按标准 P/R 调和平均。
报告方式：IoU Hit@0.5 为主指标（与 Snappy/RegionRAG 对表），Text-Recall@0.8 为辅指标。
凡 IoU 未命中但 Text-Recall ≥ 0.8 的样本单独成组（疑似解析边界误差），人工抽查 ≥20 例判定。
防刷分：预测框面积超过页面 50% 的样本 Text 分数置零或单独标注，禁止用超大框刷文本命中。
```

### 8.4 公平比较

所有方法必须使用相同的 query、页面集合、数据划分和评测脚本。不能把不同 query 子集或不同 top-k 结果放在同一张表中比较。无框 query 不计入区域分母；跨页证据单独标注，不混入单页区域分。

## 9. 代码与项目开发规范

新实验项目只保留以下职责：

```text
src/       正式实现
configs/   数据、模型和实验配置
scripts/   清晰的运行入口
tests/     单元测试和最小 smoke test
docs/      当前有效的研究和实验说明
runs/      每次运行的不可变结果
artifacts/ 模型、索引和缓存等可再生成文件
```

每次实验至少保存：

```text
config.json
run_info.json
metrics.json
summary.md
predictions.parquet（如适用）
```

代码变更通过 Git commit 追踪；实验结论通过单独的实验记录追踪；不再创建多个互相矛盾的 change log 或 current results 文件。

补充：旧仓库 `docs/literature/` 每月重扫一次 arXiv（Snappy/Beyond/RegionRAG/Argus 若出可学习变体，我们的空间会被压缩，速度优先）。对照表（第 4 节）随重扫更新，更新只增行不改旧结论。本仓库 literature 按批次 6 迁入后执行同一节奏。

## 10. 论文创新表述边界

在没有完成系统查重前，建议使用：

> 本文设计并实现一种布局约束的稀疏文档侧 patch 融合方法，在不裁剪页面和重复视觉编码的条件下，利用 OCR/Layout 区域信息学习增强的视觉 patch 表示，并在页面检索和证据区域定位任务上进行系统评估。

不应直接使用“首次”“完全没有工作做过”之类表述。需要通过与 Beyond Bag-of-Patches、ColParse、Snappy、RegionRAG 及其他相关方法的输入、训练方式、表示位置、推理接口和区域评测进行逐项对照后，才能确定真正的新颖性范围。

创新成立的六条检查项（一条不满足就不写进贡献）：有可训练参数、有独立训练数据、非测试集调参、有明确对照（Snappy/RegionRAG/ColParse/ColMate）、三指标同报、证明不是“加 OCR 就有效”。Gate、残差、zero-init、坐标映射、统一评价、不重复编码都不单列创新。

## 11. 进入下一阶段的 Gate 与风险停止条件

```text
Phase 1A 完成并核验数据规模
    -> 才能做 Phase 1B
Phase 1B 得到 A/B/C/D 统计
    -> 才能做 Phase 1C
Phase 1C 三类无训练 baseline 完成
    -> 才能训练 Phase 2 模块
Phase 2 在 dev 有稳定提升
    -> 才能冻结配置并跑最终 test
```

任何阶段如果没有达到 Gate，应先修复数据、代码或实验协议，不能通过增加复杂模块来掩盖基础实验不可靠的问题。

### 11.1 停止/收缩条件（出现任一条即停）

- 坐标映射审计不通过（resize/padding/网格对不上）；
- BBox 与页面图像系统性错位；
- 区域标签无法可靠构造（无独立训练数据又要用 evaluation gold 训练）；
- 新模块只涨 test、dev 不涨；
- 页级掉分且区域不涨；
- 复杂融合不如固定 IoU 聚合；
- 训练成本超 3080Ti 12GB 可承受范围；
- Snappy 已解决大部分缺口（定量判定见 11.2，此时按 11.3 收缩，不强行堆模块）。

科学风险重申：query-independent 融合可能污染页级匹配（Beyond 消融：去 global 只掉 0.3~0.4；Argus 消融：去 query 条件掉 3~4 分）。我们没有 query 条件，增益天花板必须由 1B/1C 数据回答，不能预设网络一定有效。

### 11.2 Gate 的定量判定口径（数字 dev 定，test 不改）

“稳定存在”“解决大部分缺口”必须落到数字，且必须注明计算条件（Top-K、IoU 阈值、query 子集）：

```text
进 Phase 2 需同时满足：
  a. B 类占比 ≥ 10%（有布局 gold 的 1598 query 上，IoU≥0.5，Top-K 同 1B config）；
  b. Snappy 三聚合中最好者只消掉 B 类的 ≤ 50%；
  c. a/b 在 dev 与 test 划分上趋势一致（正式划分文件见执行手册）。
停 Phase 2（转收缩）为上述任一条不满足的相反面，即：
  B 类占比 < 10%，或 Snappy 已消掉 ≥ 50% 的 B 类，且趋势一致。
10%/50% 是初始值：dev 数据出来后允许修正一次，修正必须写进执行手册的冻结表并给出 B 类分布直方图作为依据，之后不再改动。
```

### 11.3 有序收缩选项（Plan B，按成本从低到高，触发即逐级评估）

- B1 效率与压缩角度：0 次额外编码 vs LFRAG/ColParse 的 k+1 次，同表对比存储、索引、延迟、显存（数据全部来自 1C，无新实验成本）；
- B2 失败分类学：OCR 天花板（Snappy 85% 口径）+ 1B 的按类型/面积/OCR 密度分层缺口归因，转为一篇“诊断 + 基准”型论文；
- B3 跨页证据 / 复杂表格布局解析：只有 1B 数据证明单页区域定位已到顶、且 MMDocIR 中跨页样本量足够时才立项，需另立 Gate 与协议，不许自动 fallback。

B1/B2 不需要新数据，保住小论文下限；B3 是新研究，不是救命稻草。选择必须由学生与导师共同确认后写入执行手册，agent 只准备决策材料（分层表、残差分布、直方图），不做选择。
